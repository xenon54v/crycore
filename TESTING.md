# CryptoCore Testing

## Sprint 3 — CSPRNG testing

В Sprint 3 был добавлен отдельный модуль CSPRNG для генерации криптографически стойких случайных данных.

Для генерации используется функция:

```python
generate_random_bytes(num_bytes: int) -> bytes
```

Внутри используется системный источник случайности `os.urandom()`.

## Автоматические тесты

Для запуска всех автоматических тестов проекта:

```powershell
pytest -v
```

В рамках Sprint 3 дополнительно проверяется:

- генерация случайных байтов требуемой длины;
- обработка некорректного размера;
- генерация 1000 уникальных 16-байтовых ключей;
- базовое распределение битов;
- автоматическая генерация AES-128 ключа при отсутствии `--key`;
- успешное шифрование и последующее расшифрование с автоматически созданным ключом;
- обязательность `--key` при расшифровании;
- предупреждение о слабом пользовательском ключе;
- сохранение interoperability-тестов с OpenSSL.

## Подготовка данных для NIST STS

Для статистической проверки CSPRNG используется скрипт:

```text
scripts/generate_nist_data.py
```

Он создаёт бинарный файл:

```text
nist_test_data.bin
```

Размер файла:

```text
10 000 000 байт
```

Это соответствует:

```text
80 000 000 бит
```

Данные полностью генерируются через функцию `generate_random_bytes()`.

Запуск генерации:

```powershell
python scripts/generate_nist_data.py
```

## NIST Statistical Test Suite

Для проверки был использован NIST Statistical Test Suite версии 2.1.2.

Тестирование выполнялось в WSL2 / Ubuntu.

Программа запускалась командой:

```bash
./assess 1000000
```

Длина одной анализируемой последовательности:

```text
1 000 000 бит
```

Количество последовательностей:

```text
80
```

Формат входных данных:

```text
Binary
```

Были запущены все 15 статистических тестов NIST STS.

Использовались стандартные параметры:

```text
Block Frequency Test: M = 128
NonOverlapping Template Test: m = 9
Overlapping Template Test: m = 9
Approximate Entropy Test: m = 10
Serial Test: m = 16
Linear Complexity Test: M = 500
```

## Результаты NIST STS

Итоговый отчёт сохранён в:

```text
docs/nist/finalAnalysisReport.txt
```

Для выборки из 80 последовательностей минимальная допустимая доля успешных последовательностей составила:

```text
76 / 80
```

Для Random Excursions и Random Excursions Variant анализировалось 47 подходящих последовательностей, минимальная допустимая граница составила:

```text
44 / 47
```

Примеры результатов:

```text
Frequency               78/80
BlockFrequency          80/80
CumulativeSums          78/80
Runs                    80/80
LongestRun              80/80
Rank                    77/80
FFT                     79/80
Serial                  80/80
LinearComplexity        79/80
```

Команда:

```bash
grep '\*' experiments/AlgorithmTesting/finalAnalysisReport.txt
```

не вывела ни одной строки.

Это означает, что итоговый отчёт NIST STS не содержит тестов, помеченных как не прошедшие по критериям набора.

Отдельные P-value ниже `0.01` встречались в отдельных строках Random Excursions Variant, однако NIST STS не отметил их как общий провал теста, а итоговые пропорции успешных последовательностей оставались выше допустимого минимума.

## Вывод

CSPRNG на основе `os.urandom()` успешно прошёл автоматические тесты проекта, тест на уникальность 1000 ключей, базовую проверку распределения битов и полный набор NIST STS.

По итоговому отчёту статистических тестов критических отклонений не обнаружено.

## Performance testing

Для оценки производительности самописных реализаций SHA-256 и SHA3-256 было выполнено сравнение с соответствующими алгоритмами из стандартного модуля `hashlib`.

Тестирование выполнялось для входных данных размером 1 KB, 1 MB и 10 MB.

Результаты:

| Размер данных | CryptoCore SHA-256 | hashlib SHA-256 | CryptoCore SHA3-256 | hashlib SHA3-256 |
|---|---:|---:|---:|---:|
| 1 KB | 0.006653 s | 0.000078 s | 0.011012 s | 0.000164 s |
| 1 MB | 5.356635 s | 0.000993 s | 6.557257 s | 0.003237 s |
| 10 MB | 53.324647 s | 0.010689 s | 94.163030 s | 0.044448 s |

Самописные реализации CryptoCore значительно медленнее `hashlib`. Это ожидаемый результат, поскольку SHA-256 и SHA3-256 в CryptoCore реализованы непосредственно на Python в учебных целях, включая обработку блоков, раундовые функции и преобразования внутреннего состояния.

`hashlib` использует оптимизированные низкоуровневые криптографические реализации, поэтому работает значительно быстрее.

При увеличении объёма данных время выполнения CryptoCore также увеличивается примерно пропорционально размеру входных данных, что соответствует последовательной блочной обработке.

Benchmark запускается командой:

```powershell
python scripts/benchmark_hashes.py
```


# Sprint 4 — Hash Function Testing

В Sprint 4 тестируются самописные реализации SHA-256 и SHA3-256.

## Known-Answer Tests

Для SHA-256 проверяются стандартные тестовые значения.

Пустая строка:

```text
e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
```

Строка:

```text
abc
```

Результат:

```text
ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
```

Также используется длинный стандартный тестовый вектор:

```text
abcdbcdecdefdefgefghfghighijhijkijkljklmklmnlmnomnopnopq
```

Ожидаемый SHA-256:

```text
248d6a61d20638b8e5c026930c3e6039a33ce45964ff2167f6ecedd419db06c1
```

Для SHA3-256 также проверяются стандартные значения.

SHA3-256 пустой строки:

```text
a7ffc6f8bf1ed76651c14756a061d662f580ff4de43b49fa82d80a4b80f8434a
```

SHA3-256 строки `abc`:

```text
3a985da74fe225b2045c172d6bd390bd855f086e3e9d525b46bfe24511431532
```

## Chunk processing

Функции хеширования файлов читают данные блоками по 8192 байт.

Проверяются:

- пустые файлы;
- небольшие файлы;
- бинарные файлы;
- данные, превышающие размер одного chunk;
- последовательные вызовы `update()`;
- файлы большого размера.

Результаты сравниваются с `hashlib`.

## Interoperability

SHA-256 сравнивается с системной утилитой:

```bash
sha256sum
```

SHA3-256 сравнивается с:

```bash
openssl dgst -sha3-256
```

Для одинаковых входных файлов CryptoCore и системные реализации выдают одинаковые digest.

Тесты:

```text
tests/test_hash_interop.py
```

## CLI testing

Проверяется команда:

```text
cryptocore dgst
```

Тестируются:

- `sha256`;
- `sha3-256`;
- вывод в stdout;
- `--output`;
- отсутствующий файл;
- stdin через `--input -`;
- запрет параметров шифрования для `dgst`.

Команда `dgst` не принимает:

```text
--key
--mode
--encrypt
--decrypt
--iv
```

## Large file testing

Для проверки потоковой обработки реализован интеграционный тест SHA-256 для файла размером более 1 GB.

Он отключён при обычном запуске, поскольку самописная Python-реализация SHA-256 значительно медленнее оптимизированных библиотек.

Ручной запуск:

```powershell
$env:RUN_LARGE_HASH_TEST="1"
pytest tests/test_hash_large_file.py -v
```

После выполнения:

```powershell
Remove-Item Env:RUN_LARGE_HASH_TEST
```

Также SHA3-256 проверяется на большом многоchunk-файле в обычном наборе тестов.

При экспериментальном запуске самописной SHA-256 на файле более 1 GB вычисление продолжалось более 30 минут. Это связано с реализацией всех раундовых операций непосредственно на Python, а не с загрузкой файла целиком в память.

## Avalanche Effect

Для проверки лавинного эффекта во входном сообщении изменяется один бит.

После этого сравниваются два 256-битных digest.

Количество изменённых бит должно находиться примерно около половины размера хеша.

Тест выполняется для:

```text
SHA-256
SHA3-256
```

Тест:

```text
tests/test_hash_avalanche.py
```
